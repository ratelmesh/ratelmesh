RatelMesh v0.2.39

This release hardens EXIT recovery, native tunnel lifecycle handling, and the
public client release boundary.

Highlights

- Physical endpoint pins are installed before tunnel updates and retained for
  safe recovery when route operations fail.
- macOS and Linux route cleanup now matches the complete route owner rather
  than deleting another VPN or LAN route with the same prefix.
- Windows route queries fail closed, ignore disconnected default interfaces,
  and handle IPv6-only EXIT paths.
- Failed IPv6 rollback is isolated from a working IPv4 EXIT plan, so a later
  network refresh does not tear down healthy IPv4 routes.
- Incomplete route or firewall cleanup is returned as an error, remains
  fail-closed, and is recorded across daemon restarts.
- iOS start, update, stop, forced teardown, App Group storage, runtime
  statistics, and user-visible error delivery have bounded lifecycle rules.
- iOS error records use stable codes in all 13 product languages and never
  persist dynamic system descriptions, addresses, URLs, paths, or tokens.
- iOS now suppresses cached peer and EXIT state while offline and gives an
  actionable re-enrollment path when device authorization expires.
- iOS binds Keychain configuration to the current installation, completes
  interrupted credential resets after a crash, and rejects stale tunnel-provider
  IPC after the provider lifecycle has ended.
- Android credential resets are serialized across app and service instances;
  externally revoked VPN permission now stops the core and polling loop rather
  than allowing a stale tunnel to return.
- iOS blocks tunnel startup while an enrollment reset is pending. iOS, Android,
  and macOS accept remote-access targets only as strict numeric Mesh IPs with an
  allowlisted protocol and valid port, preventing authority/path/query injection.
- Android clears stale peer, address, and EXIT state during every teardown,
  wraps remote-access actions at large text sizes, and uses a proper adaptive
  launcher icon derived from the canonical brand mark.
- Android now removes the old no-backup device identity before a changed
  enrollment code or Coordinator is used, while preserving an actionable
  re-enrollment requirement across service teardown.
- macOS uses canonical micro artwork at 16 and 32 pixels, an inset menu-bar
  template that remains unclipped, large-text-safe layouts, and localized
  system location prompts in all supported languages.
- macOS validates privileged enrollment and uninstall helpers before requesting
  authorization, and bounds helper IPC reads and writes.
- Windows installation and geographic-privacy guidance now follow the selected
  language across all 13 supported locales.
- Device verification and Tenant login emails follow the selected product
  language across all 13 supported locales.
- Tenant Console logout now revokes the exact browser session durably before
  clearing its cookie. Revocations survive Coordinator restart, remain safe
  across bounded clock correction, and cannot be bypassed by replaying an
  approved onboarding request.
- Tenant browser sessions use a new version boundary so sessions issued by this
  release are rejected by an older Coordinator after a binary rollback.
- Coordinator admission now bounds global long polls, persistent node records,
  IPv6 source cardinality, forwarded-header parsing, and limiter cleanup work.
  JSON POST endpoints require the correct media type, and operational logs no
  longer include device names, Mesh addresses, key prefixes, or raw tenant IDs.
- Coordinator snapshots use a versioned, strict, bounded decoder. Recovery
  rejects truncated, duplicate-key, oversized, future-schema, symlink-swapped,
  and internally inconsistent state before serving traffic; file and Postgres
  stores use the same validation rules. Legitimate concurrent atomic snapshot
  replacement is retried without weakening symbolic-link checks.
- The production Coordinator systemd sandbox drops all Linux capabilities and
  restricts namespace, process, clock, hostname, kernel-log, realtime, and
  syscall-ABI access. The TLS edge adds HSTS, anti-sniffing, anti-framing,
  no-referrer, and browser-permission protections.
- Legacy self-signed TLS camouflage now requires an explicit certificate pin.
  Unpinned links fail closed so an active intermediary cannot recover Relay
  admission credentials; use certificate-authenticated WSS in production.
- WebSocket camouflage now strictly validates the handshake, masking direction,
  frame type, control-frame rate, and one-megabyte payload boundary. Relay and
  front-door listeners have bounded connection counts and close accepted sockets
  during shutdown; unknown transport names fail closed instead of becoming plain.
- Relay admission no longer accepts a fleet-wide fallback credential: each node
  must prove its own derived membership credential.
- Relay streams now handle short writes without corrupting frame boundaries,
  and shutdown interrupts a blocked sender so reconnect recovery cannot deadlock.
- The path-safe 1280-byte MTU is applied consistently on macOS, Linux, and
  Windows. Physical endpoint pins are limited to the address families actually
  captured by EXIT, so an unavailable IPv6 default cannot block working IPv4.
- Device capabilities have separate Ed25519 and ML-DSA signatures. EXIT and
  Relay privileges are rejected before side effects if either credential is
  absent, stale, or bound to another node key.
- Pairwise post-quantum sessions are bound to a monotonic epoch in both the
  ML-DSA transcript and WireGuard PSK derivation. Replay and same-epoch
  ciphertext substitution remain rejected after a restart.
- Remote-access policy observations persist as a trusted time floor, preventing
  an expired SSH, RDP, or VNC grant from reviving after clock rollback. A
  strictly newer authority-signed policy is the recovery boundary for an
  accidental future clock jump.
- Encrypted file-transfer receivers persist the same monotonic time guarantee
  before authenticating an offer, so an expired offer cannot revive after a
  restart and clock rollback. A strictly newer authority-signed recipient
  binding can safely recover an accidental future time floor without accepting
  offers for the retired key. Resume state, quotas, tombstones, and state-root
  locking remain authenticated and bounded.
- Shareable Network Doctor reports tokenize untrusted device labels and probe
  identifiers, classify dependency failures without serializing their raw text,
  withhold panic payloads, scrub absolute paths, and exclude repair-executor
  errors while retaining stable diagnostic and rollback status codes.
- Network Doctor is available from the Android, iPhone/iPad, and macOS clients
  in all 13 supported languages. It diagnoses Coordinator, Relay, EXIT,
  WireGuard, MTU, DNS, IPv4/IPv6, routing, and video-connectivity paths, then
  presents a redacted report that can be reviewed before sharing.
- Repairs require explicit confirmation and a short-lived, one-use plan bound
  to the selected safe action. Clients show the resulting repair and rollback
  status without exposing raw dependency or executor errors; unsupported
  repairs remain diagnostic-only.
- Native remote launchers require the advertised target address to equal the
  selected peer's authenticated Mesh IP. Assistive technology now announces
  both the protocol and target device, plus selected route state.
- Coordinator authority keys fail closed on malformed, linked, replaced, or
  overexposed files and use exclusive, fsynced creation. Restored control keys
  and post-quantum epoch floors are structurally and cryptographically checked.
- Windows installation now verifies the fixed-path WireGuard signature, every
  bundle file, managed-root/reparse and task ACL boundaries, and rolls back task,
  configuration, and files together. Windows uninstall fails closed if exact
  route, tunnel, or WinNAT ownership cannot be removed.
- Linux enrollment secrets stay out of process arguments. Client and EXIT
  installation are transactional, service directories and sockets are private,
  and the included uninstaller preserves device identity by default.
- Desktop archives are reproducible from a fixed source timestamp, publish
  only after validation, and include a staged checksum manifest.
- Android and unsigned iOS previews now have exact-commit reproducible recipes,
  deterministic checksums, signing-state declarations, and machine-readable
  provenance. Multi-file desktop output appears through a single no-replace
  directory transaction.
- The public Go module now uses `github.com/ratelmesh/ratelmesh`, and client
  publication is generated through an exact-file allowlist that rejects private
  server paths, unapproved identities, and secret-shaped content.
- The public client source now includes the complete transport-independent
  encrypted file-transfer core while keeping Relay challenge generation,
  admission-secret derivation, and verification in the private server source.
- Website release verification follows every advertised download across all 13
  languages and rejects missing, empty, or HTML fallback artifacts before
  deployment. Topology visuals now expose meaningful screen-reader roles.
- Unknown Tenant login addresses receive an indistinguishable decoy challenge
  without consuming the bounded durable challenge store, so distributed account
  probing cannot crowd out legitimate login attempts.
- The download edge preserves upstream 404 and valid unsatisfied-range 416
  responses, forwards If-Range, and never emits a body for HEAD. Coordinator
  replacement now restores the previous binary atomically when its final
  socket, service, or health gate fails.
- The text-processing dependency is updated to remove the reachable
  GO-2026-5970 vulnerability.

Upgrade note

- Existing Tenant Console sessions are intentionally invalidated once when the
  Coordinator moves to the new session version. Sign in again by email; device
  tunnel credentials and mesh enrollment are not removed.
- Self-hosted deployments advertising an unpinned `tlscamo` Relay must move to
  authenticated WSS before upgrading clients. DIRECT and existing WSS paths are
  unaffected.
- Coordinator snapshots larger than 64 MiB, from a future schema, or containing
  ambiguous/inconsistent records now fail closed and require offline audit
  before startup.
